# Бриф: новый движок (engine2), исполнитель — Fable

**Решение владельца, 2026-10-13.** Пишется новый движок, спроектированный заново с учётом опыта
нынешнего. **Это не перенос** старого кода и не перенос старых правил контента. Старый движок
замораживается и остаётся рабочей игрой, пока новый не пройдёт приёмку.

`docs/refactoring_brief.md` этим решением **отменён**: рефакторить код, который заменяется, незачем.
Идеи `docs/adaptive_engine_brief.md` — сторож вырождений, решения акторов, тяга к норме — **встроены
сюда с первого дня**, а не добавляются слоями.

## 00. Жанр: симулятор альтернативной истории

**Реальная история — только точка старта, а не сценарий развития** (владелец, 2026-10-13).
Сценарий — снимок мира на дату расхождения: кто есть, где, сколько, чего хочет. Дальше мир развивается
сам, от решений игрока и акторов. Обязательных событий нет.

Что из этого следует для всего брифа:
1. **Исходы свободны.** Реальный ход событий — лишь один из возможных исходов, и он не должен
   выпадать сам по себе в большинстве партий. Сторож ловит обратное (флаг `history_lock`, §6).
2. **Механика правдоподобна, исходы — нет.** Рост населения, размер армий, доходы держатся в
   правдоподобных диапазонах эпохи (§2): альтернативный мир должен быть убедителен, а не произволен.
3. **Никаких дат после старта.** Нынешние «вехи по дате» (`rome_splits` на тике 40 в 30 из 30,
   `huns_visible`, `ludovico_takes_regency`) — именно то, чего в engine2 нет. Раскол Рима, приход гуннов,
   регентство Лодовико — **возможности**, которые наступают или нет по ходу мира.
4. **Летописец пишет историю этого мира.** Всё, что модель знает о реальной истории после даты старта,
   — источник галлюцинаций, а не подсказка (§7).

## 0. Главное требование: системы — в движке, сценарий — только данные

> «Нужно сделать всё (экономику, армию, социалку и так далее) вне сценария, но так, чтобы сценарии
> могли работать полноценно. Потому что тут идёт подгонка сценариев.» — владелец

### 0.1. Как подгонка выглядит сейчас (замер по коду, 2026-10-13)

В нынешнем движке «физика» мира лежит **в файлах сценария**, и каждый сценарий подогнан отдельно:

| что | где | как подогнано |
|---|---|---|
| связи метрик (`dependencies.toml`) | все три сценария | одни и те же 15–16 правил **скопированы трижды** и разошлись: `population_to_economic_output` — `5e-05` от `3000` в rome и constantinople, `0.0002` от `500` в milan; `cohesion_natural_decay` — 0.12 / 0.10 / нет |
| доход казны | `economy_v2_income_coefficient` | 0.001570 / 0.001516 / 0.001538 — по сценарию |
| вероятность войны | `military_conflict_probability` | 0.45 / 0.20 / 0.35 |
| пол легитимности ранга S | `rome_375/rank_bonuses.toml` | 20 → 12 по свипу 60 сидов, чтобы Рим вообще мог погибнуть (A11) |
| дрейф по актору (`auto_deltas`) | constantinople 27, milan 20 | например, армия Османов +0.5 за тик при `federation_progress > 40` — сюжет, записанный как число |
| теги | `tags.toml` | теги несут прямые дельты метрик (`regency_crisis`: легитимность −2, сплочение −1 за тик) — корень насыщений (A46) |
| действия игрока | `actions.toml` | каждое с ручными числами по конкретным акторам (`venice.cohesion +3`, `milan.treasury −60`) |
| исторические события | `milestone_events.toml` | события по порогам абстрактных метрик (`naples.external_pressure > 80` два тика → «Отранто пало») |
| роль игрока | код сценария | три разные модели: семья внутри Рима, коалиция без актора в Константинополе, держава в Милане |

Каждая задача баланса последних месяцев правила одно из этих чисел для одного сценария. Отсюда вечный
цикл: поправил число — сдвинулся другой сценарий или другой исход.

### 0.2. Правило

**Движок** владеет всеми правилами и всеми константами — одна таблица параметров на все сценарии.
**Сценарий** описывает мир, а не то, как мир работает:

| в сценарии **можно** | в сценарии **нельзя** |
|---|---|
| акторы, их география, регионы, рёбра карты | коэффициенты, темпы, вероятности |
| начальные количества **в единицах мира**: люди, солдаты, кг пшеничного эквивалента (монеты — только словарь показа, E0 §5 Э1б) | пороги по метрикам, дельты метрик |
| устройство: тип власти, правитель, дом, возраст, наследник | правила «метрика → метрика» |
| культура, религия, институты (из закрытого перечня движка) | дрейф по актору |
| отношения на старте: союзы, вассалитет, войны, браки | числа в действиях |
| стартовые устремления акторов и внешние силы (§4) | события по порогу абстрактной метрики, события по дате |
| роль игрока из перечня движка, цель из перечня движка | своя модель игрока |
| набор доступных глаголов (§3) и их названия | — |
| имена, тексты, контекст летописца, `forbidden_claims` | — |

**Если сценарию не хватает механики, это пробел движка, а не повод для исключения.** Механика
добавляется в движок как общая система, доступная любому сценарию. Пример: «семья внутри державы»
нужна Риму, но то же самое — Сфорца в Милане и Палеологи в Константинополе. Ветки кода под конкретный
сценарий запрещены.

### 0.3. Проверка правила — «сценарий без подгонки»

1. **Схема сценария не содержит числовых полей правил.** Это проверяет тип: в структуре сценария нет
   поля, куда можно записать коэффициент. `deny_unknown_fields` везде.
2. **Движок не знает имён сценариев и акторов.** Гард (по образцу
   `engine_knows_authored_content_only_by_these_names`): ни одного литерала id в коде движка.
3. **Тестовый мир.** Синтетический сценарий из одних фактов (пять держав, карта, без устремлений) играется
   300 тиков полноценно: сторож (§6) не поднимает флагов вырождения. Это доказательство, что движок
   работает сам, а не держится на подгонке.
4. **Одна правка — все сценарии.** Изменение константы движка принимается, только если сторож не
   ухудшился **ни в одном** сценарии и в тестовом мире.

## 1. Цель продукта (решает владелец до кода)

Без цели новый движок повторит A46: калибровку без цели. Ответы владельца от 2026-10-13 помечены
**утверждено**; остальное — предложения, решение за владельцем (§11).

| вопрос | предложение | почему |
|---|---|---|
| **Кем играет игрок?** | **утверждено:** две роли движка — **правитель державы** и **дом внутри державы**. Коалиция Константинополя — дом (например, Палеологи), который строит союз | три нынешние модели сводятся к двум общим |
| **Что должно зависеть от игрока?** | исход (кто жив, кто кому подчинён, чья цель достигнута) различается между стратегиями игрока, парно по сидам | разброс по сидам дёшев, но игроку ничего не даёт |
| **Что фиксировано?** | только стартовый снимок (§00). Обязательных событий нет; внешние силы (гунны, Османы) — участники мира со своими устремлениями | жанр альтернативной истории |
| **Насколько мир «тянет» к реальной истории?** | **утверждено:** стартовые устремления исторические, а дальше могут уходить в альтернативу. Повторение реального хода событий допустимо, но не постоянно (`history_lock`, §6) | иначе получится тот же «всегда одно и то же», только под видом истории |
| **Масштаб карты** | **утверждено: провинции и отряды входят в engine2** (§2a). Держава владеет провинциями, армии — отряды на графе провинций | война и распад становятся территориальными, а не потерей метрик |
| **Время** | контракт прежний: 2 тика = 1 год (AGENTS §1) | на нём стоят летописец, сохранения и дата старта |
| **Победа и поражение** | **открыто.** Предложение: жёсткой победы нет. Игрок на старте выбирает устремление из перечня своей роли (выжить, возвысить дом, подчинить, объединить, удержать), а в конце партии движок подводит итог: что достигнуто, что потеряно. Экран победы — когда устремление достигнуто, с правом продолжать (как сейчас после E) | сейчас победа — порог метрики, записанный в сценарии; в альтернативной истории итог важнее финиша |

## 2. Модель мира — системы движка

Общие правила для всех систем:
- **Единицы мира, а не 0..100**, где у величины есть природа: люди, солдаты, килограммы
  пшеничного эквивалента в год (деньги — словарь показа, `engine2_e0.md` §5, Э1б). Шкалы
  0..100 — только для оценок (легитимность, единство), и у каждой есть норма.
- **Запас = поток.** У каждого запаса явные источники и стоки, и движок может вывести их баланс за
  тик (урок «армия без источника», казны, миграции задачи 26).
- **Тяга к норме вместо клампа.** Норма выводится из состояния; события, теги и решения сдвигают
  **норму** или дают разовый толчок, а не темп за тик (урок A46: тег как темп → насыщение).
  Граница шкалы — проверка инварианта: если она сработала, это флаг сторожа.
- **Константы — в одном файле движка** (`engine2/params.toml`), каждая с единицей и
  правдоподобным историческим диапазоном. Это даёт проверку, независимую от «как играется»: рост
  населения 0,1–0,5 % в год, постоянная армия 0,5–1,5 % населения в мире и 2–3 % в войну и т. п. (диапазоны — `engine2_e0.md` §5, утверждает владелец).

| система | запасы и оценки | что приходит из сценария |
|---|---|---|
| **Население** | люди; рост к ёмкости земли, голод, мор, миграция с сохранением суммы | начальное население, регион (ёмкость из географии и эры) |
| **Экономика** | производство из людей, земли, торговли и порядка; казна как поток доходов и расходов; налог, долг | ничего, кроме фактов: торговые рёбра (суша/море), институты (банки, порты) |
| **Армия** | солдаты, набранные из населения; содержание из казны; качество из опыта и институтов; мобилизация и роспуск — решение; бой с победителем и концом; осада | начальная армия в людях, институты (наёмники, флот) |
| **Внутренняя политика** | легитимность правителя, единство элит и регионов, дома и фракции; мятеж; **наследование**: смерть правителя, малолетний наследник → регентство → кризис как общий механизм | правитель, возраст, наследник, дома |
| **Угроза** | вычисляется из соседей (сила, намерение, расстояние), а не хранится храповиком | — |
| **Дипломатия** | отношения пар, союзы, вассалитет с данью, браки, договоры со сроком | стартовые отношения |
| **Религия и культура** | трение пар, распространение по общим каналам (торговля, завоевание, брак) | культура, религия |
| **Распад и наследники** | распад по регионам и культурам при потере единства; наследник получает рёбра родителя | ничего: наследники выводятся из регионов, культур и домов. Реальные государства-наследники (Западная империя, остготы) — лишь один из возможных исходов |
| **Эры** | общая таблица по году: военные технологии, мореходство, финансы | — (год старта) |

Регентство Милана — показательный пример. Сейчас это тег `regency_crisis` с дельтами и датой
окончания, записанные в сценарий. В engine2 это общий механизм наследования: в 1476 году убит
правитель, наследнику семь лет. Кризис и его исход следуют из механизма и решений домов. Лодовико
может взять регентство, может проиграть Боне Савойской, может погибнуть — даты 1480 в движке нет.

## 2a. Территория: провинции и отряды (утверждено владельцем)

- **Провинция** — единица земли: население, ёмкость, доход, культура, религия, укрепления, порт.
  Население и экономика из §2 живут в провинциях; держава — их владелец и сумма.
- **Граф провинций** заменяет списки соседей акторов: соседство держав выводится из соседства их
  провинций (сейчас рёбра акторов пишутся руками и ломались при наследовании — задачи о рёбрах
  наследников и спавнов).
- **Отряд** — армия с численностью, качеством, командиром и положением; движется по графу, снабжается
  из провинций, осаждает, отступает. Бой — между отрядами в провинции, а не между державами вообще.
- **Война меняет владельца провинций**; распад — это отделение провинций по культуре и регионам,
  наследник получает провинции, а не копию метрик.
- **Данные карты — новые.** Сейчас у каждого актора один полигон (`map.toml` + geojson), провинций нет.
  Геоданные провинций — отдельный шаг **E1b** и задача только про карту (AGENTS §11 к старому движку
  не относится, но правило «карта — отдельная задача» сохраняется). Старая карта не меняется.
- **Объём (предложение):** провинций — десятки на сценарий, а не сотни; отряд — один-несколько на державу. Глубже —
  только если этого требует цель.

## 3. Агенты: решают все, движок исполняет

- **Одни глаголы для всех.** Набор действий — перечень движка: набрать или распустить войско, нанять
  наёмников, объявить войну, заключить мир, предложить союз или брак, подкупить, взять заём, поднять
  налог, укрепить порядок, отправить посольство. Игрок и неигровые акторы пользуются **одними** правилами
  доступности и цены (урок B42). Сценарий только включает подмножество глаголов и даёт им имена.
- **Эффект глагола считают системы** из состояния (брак даёт отношения в зависимости от домов, а не
  «+3 к сплочению Венеции»).
- **Полезность без обучения:** простая функция состояния и целей актора; выбор — `softmax` с
  температурой из `params.toml`, через RNG мира. Тот же сид даёт ту же игру.
- **Сначала все решают, потом всё применяется** — без попарной мутации в алфавитном порядке.
- **Цели актора** — из перечня движка (выжить, расшириться в сторону X, подчинить Y, удержать Z).
  Стартовые устремления задаются здесь (§4): Османы хотят подчинить Византию данью — это цель, а не
  `+0.5 армии за тик`. Цели **меняются** по ходу мира: разбитый, обедневший или занятый другой
  войной актор пересматривает их.

## 4. Устремления и внешние силы — без дат

Сценарий не говорит «так было» после даты старта. Он говорит «так хотели и так было устроено на
старте»:

| вид | пример | как работает |
|---|---|---|
| **стартовое устремление** | Османы хотят подчинить Византию (дань); Константинополь — возможность, не стартовая цель (E0 §6.2); Венеция — торговые пути; Лодовико — власть в Милане | смещение полезности агента на старте; дальше цель живёт и меняется по правилам движка |
| **внешняя сила** | степь за Дунаем, откуда могут прийти гунны | актор у края карты со своими устремлениями и механикой давления; приходит или нет по ходу мира, а не в 376 году |
| **устройство** | Римская империя — одна держава с двумя дворами; Милан — малолетний герцог и регентша | общие механизмы распада и наследования делают раскол или регентский кризис возможным, а не обязательным |

Устремление сформулировано в фактах мира (город, регион, путь, трон), а не в порогах метрик.
Список устремлений на сценарий утверждает владелец (§1).

## 5. Правила проектирования (уроки нынешнего движка)

Каждое правило — дефект, за который уже заплачено. Ссылки — для понимания, код не переносить.

1. **Детерминизм по построению.** Состояние — в упорядоченных коллекциях (`BTreeMap`, векторы по id).
   Один поток RNG, вытягивания в явных точках. Порядок сложения `f64` не зависит от хеша. Сохранение
   восстанавливает биты (`d3-determinism-sorted-iteration`, B21, B31, D7, порядок журнала событий).
2. **Типы вместо строк.** Метрики, акторы, события, глаголы — перечни и типизированные id. Нет
   «голого имени, молча разрешённого в глобал» (десять сайтов §5.G, задача 13).
3. **Тяга к норме, а не темп и кламп** (§2; A46, A33, A37, экономика v2).
4. **Сохранение запасов** (§2; армия без источника, миграция задачи 26).
5. **Бой с победителем и концом** (81–95 % боёв против пустой армии, Ц4).
6. **Жизненный цикл актора явный:** вход, распад, наследник с рёбрами, гибель. Нет висячих ссылок и
   чтений мёртвых (B44, задачи о наследниках и рёбрах).
7. **У каждого поля контента есть читатель, у каждого условия — достижимость.** Веха не открыта на
   тике 0 (A2, A31; гарды мёртвого авторского контента).
8. **Игрок и бот — одни правила** (B42).
9. **Учёт с первого дня:** каждая запись запаса подписана источником (как `census`, но всегда
   включаемый) — бюджет любого запаса выводится, а не пересчитывается зондом.
10. **Сторож в CI с первого дня** (§6).

## 6. Сторож вырождений — часть движка

Как в `adaptive_engine_brief.md` §2, но **независимо от движка**: он читает поток типизированных событий
и наблюдение мира за тик через общий интерфейс. Поэтому одним инструментом меряются **оба** движка на
одних сценариях — это и есть доказательство «новый лучше» вместо старой регрессионной базы.

Флаги: прижатость к границе шкалы, срабатывание границы, «никогда», «всегда», чтение отсутствующего,
застой, исход не зависит от стратегии игрока, исход не зависит от сида, **`history_lock`** — партия
без игрока повторяет реальный ход событий почти всегда (порог утверждает владелец). Для альтернативной
истории это такое же вырождение, как «всегда одно и то же». База флагов
закоммичена; гард в CI на коротком прогоне; полная матрица — перед мержем PR, который меняет мир.
Исключение без письменной причины не принимается.

## 7. Архитектура

- **Новый крейт** `engine2/` в воркспейсе. Старый `engine13` не трогать, кроме того, что мешает играть.
- **Оболочка остаётся:** `src-tauri`, UI, слоты сохранений, провайдеры LLM, книга хроник, летопись.
  Она переходит на явные контракты:
  - `Simulation`: создать из сценария, тик с действиями игрока, представление для UI, снимок для
    летописца, сохранить/загрузить;
  - **типизированный поток событий** вместо разбора id по префиксу (сейчас `annals.rs` ищет
    `"military_conflict_"`, `"vassalage_form_"`, `"spawn_"`);
  - **модель представления для UI** вместо зеркала `WorldState` в `src/types/index.ts`.
- **Оба движка за одним контрактом.** `src-tauri` выбирает движок по сценарию; сценарий переключается,
  когда engine2 прошёл приёмку на нём.
- **Летописец:** снимок (`NarrativeWorldSnapshot`) и промпт сохраняются по смыслу; собирать снимок из
  представления engine2. Разбор хроник (`investigation_chronicle_step3.md`) повторить на новом мире.
  Два изменения под жанр:
  - промпт прямо говорит модели: мир разошёлся с известной историей в дату старта, и реальные события
    после неё **не действуют**, если их нет в состоянии мира. Это общее правило в `forbidden_claims`
    каждого сценария (сейчас там только частные: «не утверждать, что Милан пал…»);
  - образ летописца берётся из эпохи сценария: **сделано в старом движке, PR #274** — век из года
    хроники (`llm::century_words`), обзор — поле `NarrativeConfig::horizon`. Перенести как есть.
- **Контракты AGENTS.md**, которые остаются: время, снимок летописца, карта, «новый прогон ≠ загрузка»,
  UI не маскирует дефекты модели.

## 9. Что берётся из старого проекта

- **Берётся:** стартовые факты сценариев (акторы, имена, карта, регионы, культура, религия, правители),
  тексты (`llm_context`, контекст последствий, `forbidden_claims`, эры), нарративный слой (промпт,
  провайдеры, идея летописи), UI, Tauri, слоты сохранений, **идеи** гардов, документы с выводами —
  как знание о том, где ломается.
- **Не берётся:** код движка, `dependencies.toml`, `auto_deltas.toml`, `rank_bonuses.toml`, дельты
  тегов, числа действий, пороги и даты вех, числа баланса, регрессионная база старого движка.
  Тексты `llm_context` перечитать: где они пересказывают реальную историю после старта
  («Отранто взято османским десантом»), это превращается в возможность, а не в факт.

## 10. Стоп-правила

- **Сценарию нужно число** → это пробел движка. Остановиться и спроектировать общий механизм; не
  добавлять поле в схему.
- **Константа поправлена ради одного сценария** и ухудшила другой → не принимается.
- **Новая система или глагол вне цели продукта** (§1) → не делать, записать вопросом владельцу.
- **Сторож нашёл вырождение** → чинить механизм, а не добавлять исключение; исключение — только с
  письменной причиной, что это задумано.
- **Старый движок** → только то, что мешает играть сейчас.
