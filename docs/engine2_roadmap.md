**Шаг 2 — оборона по сторонам объявления соседа.**

Ошибка в main, сверено по коду:

- Угроза от соседа `t` считается в `World::wars_a_tick_from` (`worth.rs`). Доля державы `a`
  там — `1 − war_odds(a, t)`.
- Стороны при этом берутся из `war_sides(a, t)` — как будто войну объявляет `a`. Для ещё не
  открытой войны это `war_entrants(a, t)`: с `a` только его вассалы, с `t` — его союзники,
  сюзерен и вассалы.
- По §19 союзник вступает в войну, объявленную **на** державу. Значит, у `a` в обороне нет
  его союзников и сюзерена, зато у `t` лишние.
- Бот завышает угрозу и держит лишнее мирное войско.
- Правило мира и оценка бота разошлись — а `war_sides` существует ровно для того, чтобы этого
  не было (§28.1).

Правка с ветки (г2): `defence_odds(a, t)` — те же стороны, что сделает объявление `t` на `a`,
то есть `war_sides(t, a)`, и та же формула боя.

Ожидание: армия мира опустится (на (г2) плато упало почти вдвое). Сейчас А11 в мире 0,0156 —
середина полосы [0,005; 0,03].

Шаг стоит до развилки: развилка решает, почему армии такие, и решать это надо на верной
оценке угрозы.

## 3. Роли и процесс

| кто | делает | не делает |
|---|---|---|
| **Владелец** | решения по вопросам плана; команда на мерж; запуск новых сессий | — |
| **Рецензент** (отдельная сессия) | планы с решениями до кода; рецензия кода; свой перемер чисел; этот файл; задачи исполнителю | код движка |
| **Исполнитель** (отдельная сессия) | код, тесты, замер, свой раздел плана «сделано» | решения за владельца; подбор чисел (§24.1) |
| **Картограф** (отдельная сессия) | данные карты, `engine2_map.md`, тесты карты | код движка |
| **Новая сессия под задачу** | одна задача из §5, своя ветка, свои файлы | файлы основной линии (§4) |

**Правила, которые держат процесс:**

1. Каждое изменение — черновой PR. Мерж — только по прямой команде владельца.
2. План до кода. Стоп без подбора (§24.1): при стоп-условии — числа, разбор и кандидаты, но
   ни одного подобранного числа.
3. Числа исполнителя рецензент перемеряет сам: отдельный worktree и свой `CARGO_TARGET_DIR`.
   Общий target однажды дал ложное равенство.
4. В конец `engine2_e1_plan.md` пишет один участник за раз. Свой раздел исполнитель пишет
   после мержа плана рецензента; рецензент — после мержа раздела исполнителя. Сессии из §5 в
   план не пишут: их вывод — свой файл, а в план его переносит рецензент.
5. `src-tauri/` вне воркспейса: менять его можно только с явной причиной, а каждый изменённый
   файл добавлять в коммит по имени (AGENTS.md).

**Нужен ли отдельный рецензент.**

- **Для шагов, которые меняют правила мира или поведение ботов, — да.** Независимый перемер
  ловил ошибки, которые автор пропустил: ложное равенство из-за общей папки сборки, двойной
  учёт походной надбавки. Ошибки при этом находили обе стороны.
- **Для документов, инструментов и мелких правок без перемера** хватает одной сессии.

## 4. Что можно вести параллельно

**Основная линия — строго одна.** Шаги, которые меняют поведение ботов или правила мира,
идут по одному. Это файлы `engine2/src/agents.rs`, `worth.rs`, `economy.rs`, `army.rs`,
`diplomacy.rs`, `params.toml`, `tests/agents.rs`. Каждый замер идёт против прошлого main: два
изменения сразу смешают и эффект, и базу.

**Параллельно с ней можно** — в своей ветке от свежего main и в своих файлах. Задания — в §5.

| работа | кто | файлы | условие |
|---|---|---|---|
| План следующего шага, если он не зависит от замера текущего | рецензент | раздел плана | в план — по правилу 4 §3 |
| Источники для списка «на E4» | картограф (§5.2) | `engine2_map.md` | только документ; правка схемы — шаг 10 |
| Согласование полос источников (кандидат 6 §30.13) | новая сессия (§5.3) | новый файл в `docs/` | только документ; `params.toml` не трогать |
| Тексты milan для E4 | новая сессия (§5.4) | новый файл в `docs/` | черновик: схема E4 не утверждена; старый движок не править |
| Подготовка E5 | новая сессия (§5.5), **только по решению владельца** (бриф ставит E5 после E4) | `src-tauri/`, `src/` | только через публичный контракт `Simulation`; engine2 не править |
| CI: задача rust разбита на три параллельные; PR только с `docs/` тесты не гоняют | рецензент | `.github/workflows/ci.yml` | решение владельца 2026-11-13; файлы линии не трогает |

**Как не мешать друг другу:**

- одна сессия — одна ветка — свой набор файлов; общий файл — значит не параллельно;
- у каждой сессии свой `CARGO_TARGET_DIR`;
- параллельная работа не меняет базу замера: `params.toml` и правила мира — только линия;
- старый движок (`src/`, `src-tauri/`) трогается только для того, что мешает играть сейчас
  (бриф §10), и в E5.

## 5. Кому что передавать

**Как передавать.**

- **Исполнителю и картографу** — в их существующие сессии.
  - Исполнителю задачу шлёт рецензент сообщением между сессиями, после ответов владельца.
  - Картографу передаёт владелец: рецензент не знает его сессию.
- **Новая сессия** — владелец открывает её на этом репозитории и вставляет текст задания из
  этого раздела как первое сообщение. Каждый текст самодостаточен.
- **Результат любой задачи** — черновой PR. Рецензент его смотрит, владелец мержит.
