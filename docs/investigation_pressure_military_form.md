# Форма зависимости `external_pressure → military_size`

**Стадия 1 — обход и измерение, без правок движка и контента.**
База: `main` = `c153440`. Ветка свидетельства: `investigate/pressure-military-form`
(**NOT FOR MERGE**: трассировка зависимостей в движке, режим `ExcessProportional`,
`dependency_probe`, переключатели в `sim`).

Постановка из очереди: «абсолютная потиковая величина, применяемая к армиям,
различающимся в сорок раз». Эта формулировка проверена и оказалась **заниженной**:
разброс цены правила по акторам — **190× / 124× / 234×** в rome / constantinople /
milan.

---

## 1. Обход, а не поиск одного правила

Искать «то самое правило» — значит заранее знать ответ. Пространство, в котором
живёт дефект, перечислено целиком: **все 47 правил зависимостей трёх сценариев**
(`rome_375` 16, `constantinople_1430` 15, `milan_1477` 16), классифицированные по
**шкале цели**, потому что именно шкала решает, значит ли абсолютная дельта одно и
то же для Рима и для Урбино.

Шкала берётся не на глаз, а из движка: `phase_clamp` держит `legitimacy`,
`cohesion`, `military_quality`, `economic_output`, `external_pressure` в `0..100`;
`military_size` и `population` — только снизу; `treasury` не клампится вовсе.

| класс цели | правил (на сценарий) | правила |
|---|---|---|
| ограничена `0..100` — одна шкала для всех | 12 | двенадцать правил, включая три остальных выхода `external_pressure` |
| безгранична, цена **на запасе цели** | 2 | `economic_output_to_population`, `low_economic_output_to_population_decay` — переведены задачей 22 |
| безгранична, цена **абсолютной дельтой** | **2** | **`external_pressure_to_military_size`**, `economic_output_to_treasury` |

**Класс дефекта содержит ровно два правила, и оба — остаток той же правки, которую
задача 22 довела только до `population`.** Второе (`economic_output_to_treasury`)
в объём этой задачи не входит и заведено «за скобками» (§10).

## 2. Инструмент

`dependency_probe` (NOT FOR MERGE) читает **собственную трассировку движка**
(`engine::dep_trace_*`): потоковый приёмник, по умолчанию выключенный, пишет
каждую применённую дельту в тот момент, когда движок её применил. Это существенно:
фаза зависимостей идёт **внутри** `phase_interactions`, после авто-дельт, рангов и
военного восстановления, так что снимок на границе тика — не то, что видят правила.

Ничего в пробнике не пересчитывает формулу заново. Это не стиль, а урок: две
рукописные копии `apply_dependency_rule` уже существуют в `budget_probe` (§10).

Контрфакты задаются на стороне сценария (пробник владеет объектом `Scenario`,
движок не трогается, ни один бросок RNG не сдвигается):
`E13_DEP_OFF`, `E13_DEP_COEF`, `E13_DEP_MODE`. При пустом окружении выход
побайтово равен базе — проверено.

## 3. Что правило делает сегодня (30 сидов × 300 тиков, без игрока)

Правило: `mode = excess`, `threshold = 50`, `coefficient = 0.01` ⇒ при насыщенном
давлении (`ep = 100`) изъятие равно **ровно 0.5 армии за тик, одинаково для всех**.

| сценарий | доля актор-тиков, где правило срабатывает | изъятие, медиана | цена в долях армии: p10 / медиана / p90 | разброс медиан по акторам |
|---|---|---|---|---|
| rome_375 | 96.2 % | 0.500 | 0.24 % / 0.96 % / 7.8 % | 0.23 % … 44.3 % = **190×** |
| constantinople_1430 | 84.2 % | 0.500 | 0.33 % / 3.2 % / 19.5 % | 0.29 % … 36.5 % = **124×** |
| milan_1477 | 98.1 % | 0.500 | 1.2 % / 5.1 % / **207 %** | 0.89 % … 208 % = **234×** |

`p90 = 207 %` в milan — не опечатка: изъятие превышает всю армию целиком, остаток
срезает кламп в ноль.

## 4. Структурный порог: кто не может держать армию вообще

С появлением источника армии (PR #62) равновесие считается в одну строку.
Восстановление добавляет `(C − m)·rate`, правило снимает `d`; равновесие —

```
(C − m)·rate = d   ⇒   m* = C − d/rate
```

При `d = 0.5` и `rate = 0.05` это `m* = C − 10`. Значит **любой актор с ёмкостью
ниже 10 не может держать армию ни при каких обстоятельствах**, а ёмкость
`C = 0.767·население^(2/3)` даёт границу по населению:

> **население < 47.1 ⇒ армия приколочена к нулю.**

Проверка предсказания против измерения — восемь акторов ниже границы:

| сценарий | актор | население (медиана) | ёмкость | армия (медиана) | тиков без армии |
|---|---|---|---|---|---|
| rome | saxons | 36.2 | 8.40 | 0.31 | 47.8 % |
| const | byzantium | 41.3 | 9.17 | 0.90 | 22.0 % |
| const | **wallachia** | 4.5 | 2.08 | **30.02** | **0.0 %** |
| milan | bologna | 42.4 | 9.33 | 0.00 | 56.2 % |
| milan | ferrara | 18.1 | 5.28 | 0.00 | 84.3 % |
| milan | mantua | 4.6 | 2.12 | 0.00 | 93.0 % |
| milan | siena | 32.2 | 7.76 | 0.00 | 61.9 % |
| milan | urbino | 15.5 | 4.76 | 0.00 | 81.5 % |

Предсказание сходится на семи из восьми, **и единственное исключение подтверждает
механизм**: `wallachia` — один из двух акторов, у которых правило не срабатывает ни
разу (§10 п. 3), и только он держит армию, вчетырнадцатеро превышающую его ёмкость.

Содержательная сторона: `urbino` без армии 81.5 % времени — это Урбино Федерико да
Монтефельтро, первого кондотьера эпохи. Модель армии это уже знала — в
`docs/investigation_military_source.md` §7 `urbino` назван среди акторов, которых
`k·pop^(2/3)` недооценивает. Абсолютное изъятие превращает недооценку в ноль.

| сценарий | гибели (актор-прогонов из 30 сидов) | актор-тиков без армии | армия, медиана | армия, p10 |
|---|---|---|---|---|
| rome, база | 153 | 3.7 % | 48.55 | 5.19 |
| rome, выкл | 120 | 0.0 % | 52.66 | 18.11 |
| const, база | 60 | 3.8 % | 19.33 | 2.40 |
| const, выкл | 60 | 0.6 % | 21.47 | 5.71 |
| milan, база | 60 | 29.3 % | 8.92 | 0.00 |
| milan, выкл | **30** | 1.4 % | 13.32 | 0.81 |

**Главный результат обхода: правило сегодня — единственный источник смертности
мелких акторов.** В milan оно даёт ровно половину всех гибелей: `siena` гибнет
30/30 в базе и 0/30 без правила. В rome оно стоит 33 гибели из 153 (`vandals`
19 → 6, `ostrogoths` 5 → 2, `alamanni` 23 → 18, `burgundians` 24 → 18).

Механизм прямой: `conquest_collapse` требует `military_size < 0.01` три тика
подряд. Ноль армии достижим **только** абсолютным изъятием — пропорциональное
затухает асимптотически и нуля не достигает.

**И ещё: полное снятие правила ломает ратифицированные ворота** — `rome scripted
influence` падает `3/3 → 2/3` (§7). Вариант «убрать» отклонён на измерении.

## 6. Кандидат: цена на запасе цели

Форма — зеркало `DeficitProportional`, которым задача 22 закрыла ту же болезнь на
`population`:

```
delta = − to · coefficient · (from − threshold) / threshold
```

При `threshold = 50` и `ep = 100` это `−to·coefficient`, то есть коэффициент
читается как **доля армии за тик при насыщенном давлении**. Равновесие становится
одинаковым для всех: `f = m*/C = 1/(1 + s/rate)`.

Свип (30 сидов × 300 тиков):

| вариант | rome гибели / без армии / армия med | const гибели / без армии / армия med | milan гибели / без армии / армия med |
|---|---|---|---|
| база (абсолютная) | 153 / 3.7 % / 48.55 | 60 / 3.8 % / 19.33 | 60 / 29.3 % / 8.92 |
| `s = 0.002` | 121 / 0.0 % / 49.62 | 60 / 0.6 % / 23.94 | 30 / 1.0 % / 13.06 |
| `s = 0.005` | 122 / 0.0 % / 48.74 | 59 / 0.6 % / 21.18 | 30 / 1.0 % / 12.47 |
| **`s = 0.01`** | **130 / 0.0 % / 47.72** | **60 / 0.6 % / 18.22** | **30 / 0.9 % / 11.72** |
| `s = 0.02` | 129 / 0.0 % / 42.20 | 60 / 0.6 % / 15.81 | 30 / 0.7 % / 10.74 |
| `s = 0.05` | 121 / 0.4 % / 28.61 | 60 / 0.6 % / 12.79 | 30 / 1.0 % / 8.08 |
| `s = 0.1` | 109 / 0.4 % / 18.31 | 60 / 0.6 % / 8.56 | 30 / 0.9 % / 5.44 |

**Смертность не восстанавливается ни при каком коэффициенте.** milan остаётся
30/60 на всём свипе; rome колеблется 109…130 против 153. Это не свойство выбора
`s`, а свойство формы: пропорциональное изъятие не даёт нуля.

Инверсия адресата видна поакторно (rome, `s = 0.01`): крупные начинают платить
больше (`eastern_jin` 0.500 → 1.890 за тик, `guptas` 0.500 → 1.626), мелкие —
почти ничего (`mantua` 0.500 → 0.005, milan).

## 8. Распределение, из которого выводится коэффициент

По правилу владельца (§10.5 п. 3 `investigation_military_source.md`) величина,
из которой выводится порог, публикуется **распределением**, а не средним.

`f = 1 − (изъятие/rate)/C` — доля ёмкости, на которой актор уравновешивается
сегодня:

| сценарий | акторов | q25 | **медиана** | q75 | мин | макс | с `f < 0` |
|---|---|---|---|---|---|---|---|
| rome_375 | 20 | 0.735 | **0.851** | 0.892 | −0.190 | 0.955 | 1 |
| constantinople_1430 | 9 | 0.268 | **0.567** | 0.665 | −0.091 | 0.948 | 1 |
| milan_1477 | 14 | −0.289 | **0.346** | 0.610 | −3.717 | 0.849 | 5 |

Сама эта таблица и есть дефект в числах: **у формы, которая должна была задавать
одно правило для всех, `f` разъезжается от 0.955 до −3.717**, и разъезжается
**по сценариям** — rome (крупные акторы) почти не задет, milan (мелкие) раздавлен.

Отсюда — коэффициент. `s = rate·(1/f − 1)`:

* сохранить медиану rome (`f = 0.851`) ⇒ `s = 0.0088`;
* сохранить медиану const (`f = 0.567`) ⇒ `s = 0.026`;
* сохранить медиану milan (`f = 0.346`) ⇒ `s = 0.094`.

Три разных числа — потому что «медиана сегодня» унаследовала перекос. **Брать их
нельзя: это значило бы вывести порог из искажения, которое правка устраняет.**
Годное утверждение одно и оно не про медиану, а про смысл: `s = 0.01` читается как
**«при насыщенном внешнем давлении держава теряет 1 % своей армии за полугодие»** и
даёт всем `f = 0.833`. Оно совпадает с сохранением медианы rome (0.0088 ≈ 0.01) —
но обосновано не совпадением, а тем, что это одно предложение о мире.

## 9. Развилка и рекомендация

**(A) Сменить форму на `ExcessProportional`, `s = 0.01`.**
Плюсы измерены: разброс цены 190/124/234× → 1× по построению; «армия ровно ноль»
3.7/3.8/29.3 % → 0.0/0.6/0.9 %; все ратифицированные ворота держатся; армия мира
почти не двигается в rome (48.55 → 47.72) и растёт в milan (8.92 → 11.72).
Цена названа и не заметается: **гибели rome 153 → 130, milan 60 → 30**
(`siena` перестаёт гибнуть совсем), `vandals` 19 → 9, `ostrogoths` 5 → 0.

**(B) Убрать правило.** Отклонён на измерении: ломает `rome influence` 3/3 → 2/3.

**(C) Отказ, форму не трогать.** Законный вариант: абсолютное изъятие — сегодня
**единственный** механизм проекта, который убирает державы, неспособные себя
защитить, и половина смертности milan держится на нём. Тогда §4 и §8 остаются
записанным свойством мира, а не дефектом.

**Рекомендация — (A).** Довод не в числах баланса, а в том, что́ правило говорит о
мире. Сегодня оно говорит: «внешнее давление отнимает у всех одинаковые 0.5 армии в
полугодие», и это утверждение неверно на собственных данных проекта — 0.5 для
Рима незаметно, а Урбино с населением 15 оно стирает начисто и держит стёртым.
Смертность, которая при этом теряется, **держалась на арифметической случайности**:
актор гибнет не потому, что его завоевали, а потому, что фиксированное число
оказалось больше его армии. Если мелкие державы должны гибнуть — это надо
сказать отдельным механизмом, а не получать побочным следствием шкалы.

**Развилка «смертность» отделена сознательно и не решается этой задачей.**

## 10. Найдено по дороге, не чинилось

1. **`budget_probe` хранит две рукописные копии `apply_dependency_rule`** (строки
   ~2353 и ~3688, плюс третья, частичная, ~1097). Найдены не чтением, а
   компилятором: добавление варианта перечисления сломало оба `match`. Кандидат в
   конвенционные гарды — по образцу гарда на типы `WorldState`.
2. **`economic_output_to_treasury`** — второй и последний член класса: абсолютная
   дельта до `−7.5` за тик на `treasury`, который не клампится ни снизу, ни сверху.
   Цена в долях запаса: медиана 2.8 % в rome, но p90 = **34 %**. Не измерялся.
3. **Два спавна constantinople правило не задевает ни разу:** `wallachia` и
   `poland_lithuania` — их `external_pressure` никогда не превышает 50, потому что
   спавн не задаёт этот ключ намеренно (задача 25). `wallachia` при этом держит
   армию 30.0 при ёмкости 2.08 — **армия, не связанная с населением вообще**.
4. `byzantium` (население 41.3, ёмкость 9.17) стоит **ниже структурного порога
   §4** — премисса сценария держится в том числе на нём.

### Чего делать нельзя

- Подбирать `s` по любому пункту критерия. Коэффициент выведен в §8 из одного
  утверждения о мире; если он не проходит — падает утверждение, а не число.
- Требовать побайтовой идентичности: правка меняет значения, значения меняют исходы
  боёв, исходы меняют число бросков RNG. Это движковая механика (урок задачи 26).
