# `(D₄)`: наследник входит в мир без рёбер

**Статус:** стадия 1 выполнена, ворота пройдены (§5), критерий объявлен (§6), стадия 2 — §7.
**Эталон:** ветка `investigate/collapse-order` `92ee88a` (стек PR #47 → #48; наследник уже входит с шаблоном дословно, гибели одного тика упорядочены). Ветка `investigate/successor-edges` — стек на #48.
**Постановка:** `investigation_successor_entry.md` §10 `(D₄)`: пять племенных шаблонов rome (`visigoth_kingdom`, `ostrogoth_kingdom`, `late_sassanids`, `vandal_kingdom_africa`, `frankish_kingdom`) объявлены с `neighbors: vec![]`, обратных рёбер у живых акторов нет — наследник входит в мир, в котором его никто не видит.

## 1. Что измерено на эталоне (30 сидов × 300 тиков без игрока)

`ostrogoth_kingdom` рождается в 27 партиях из 30, живёт 52…79 тиков (медиана 65) и гибнет **27/27** путём `internal` (`leg < 5 ∧ coh < 8`), с `population 0`, `economic_output 0`, `cohesion 0`, `treasury −2311…−3397`. Две величины за всю жизнь **не меняются ни на сотую**: `military_size = 50.0` и `external_pressure = 35.0` — авторские значения шаблона. То есть ни одного боя, ни одной миграции, ни одного производителя давления: актор существует только для собственных `auto_delta` и случайных событий. `late_sassanids` (1 рождение) — то же.

## 2. Обход: кто читает `neighbors` (все сайты вне тестов и пробников)

| сайт | что читает | чей список |
|---|---|---|
| `interactions::get_neighbor_pairs` (`:303`) | пары для торговли / культуры / дипломатии / боя / миграции / тегов | любой из двух — пара дедуплицируется, **одной стороны достаточно** |
| `interactions::calculate_military_conflict` (`:374`) | соседи для проекции силы (`effective_military`) | **собственный** список каждого из двух |
| `interactions::check_vassalage` (`:956`) | кандидаты в сюзерены | **собственный** список вассала |
| `engine::check_collapses` `besieged` (`:1529`) | есть ли вооружённый сосед на расстоянии 1 | **собственный** список гибнущего |
| `engine::check_actor_upheaval` `condition_contact` (`:1093`) | контакт с сюжетным актором, `distance ≤ 2` | список **сюжетного** актора |
| `engine::…` `has_narrative_contact` (`:1167`) | то же, в обе стороны | оба |
| `engine/mod.rs:759` | миграционное давление — **тело пустое** (комментарий, ни одной записи) | — |

Вывод обхода: «одной стороны достаточно» (правило задачи 3 про спавн) верно **только для пар**. Три читателя ходят по собственному списку, и для них у одностороннего ребра есть направление: наследник с рёбрами родителя может быть осаждён гунном, но гунн — нет, потому что в его списке по-прежнему мёртвые `ostrogoths`. Эта асимметрия **уже есть** у спавна (`france` задачи 3: `savoy` в списке Франции есть, Франции в списке Савойи нет) и у каждого актора, чей сосед погиб (висячая ссылка на мёртвого просто игнорируется — `world.actors.get(&n.id)` → `None`).

`rome_west` / `rome_east` — единственные шаблоны с **авторскими** списками (8 и 4 ребра); они не рождаются ни разу.

## 4. Равновесный расчёт — что изменится у `ostrogoth_kingdom` с рёбрами родителя

С рёбрами `huns` d1 / `visigoths` d2 / `rome` d3 наследник попадает в пары: с гуннами — бой по суше с вероятностью `military_conflict_probability` за тик (армия гуннов 120 против 50, `mq` 62), торговля/культура/дипломатия на d2–d3, миграция при `ep > 65 ∧ coh < 40` у источника. Появляются производители давления (бой) — `ep` перестаёт быть константой 35. Открывается путь `conquest` (нужны `mil < 0.01 ∧ leg < 10 ∧ ep > 85 ∧ осаждён` — гунны на d1 с армией — ровно то, от чего погиб родитель). **Ожидание, не предсказание:** наследник, скорее всего, гибнет раньше и другим путём — как родитель, от границы, а не от изоляции. Это не довод против: наследник, стоящий на месте родителя, обязан стоять на его границе. Числа — стадия 2.

## 5. Развилка и ворота

| | вариант | следствие |
|---|---|---|
| (A) | вписать пять списков руками в шаблоны | придуманная география для трёх шаблонов, которые не рождаются никогда (немеряемо); для двух — числа мои, не автора |
| (B₁) | движок: наследник с пустым списком получает список родителя | выводится из контента; один сайт; конвенция задачи 3 (одной стороны достаточно для пар); асимметрия трёх «собственных» читателей остаётся, как у спавна |
| (B₂) | (B₁) + у каждого живого актора запись `родитель → наследник`, если наследник **один** | снимает асимметрию §2 для наследования; при двух наследниках (rome → west/east) перенацеливание не определено — остаются авторские списки наследников; мутирует чужие списки в рантайме (сейв не меняется: `neighbors` и так сериализуется поактно) |
| (C) | оставить | опровергнуто §1: две константы за 65 тиков — актор не в мире |

**Решение: (B₂)** с оговоркой «один наследник». Обоснование: (B₁) закрывает пары, но оставляет три читателя с направлением — и именно они решают гибель (`besieged`) и релевантность (`condition_contact`); наследник, которого никто не перечисляет, для этих читателей не существует, что и есть дефект §1 наполовину. Авторский список наследника (`rome_west`) имеет приоритет над унаследованным; поглощение живым наследником (`savoy → milan`) **не трогается** — там наследник уже в мире со своим списком, и вопрос «наследует ли поглотитель границы поглощённого» отдельный (§8).
