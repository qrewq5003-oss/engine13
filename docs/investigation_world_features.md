# Три панели интерфейса, скрытые навсегда — и лок, который это ловит

**Статус:** выполнено одной задачей: правка + лок. Лок нашёл второй случай того же класса прямо на первом прогоне.
**Эталон:** `main` = `4aede1f`.
**Постановка:** `investigation_dead_authored_fields.md` §4 — гард на мёртвые авторские поля честно написал, чего не ловит: «поле, которое читается, но не у того объекта». `Scenario.features` был ровно таким.

## 1. Дефект

`App.tsx` гейтит три панели:

```tsx
{worldState.features?.family_panel && ( <FamilyPanel … /> )}
{worldState.features?.global_metrics_panel && ( <GlobalMetricsPanel … /> )}
{worldState.features?.patron_actions && ( <ActionHistory … /> )}
```

Флаги выставлены авторски в каждом сценарии. Но `features` жил на `Scenario`, а фронтенд читает `WorldState` — `cmd_get_world_state` возвращает `s.world_state.clone()`, и поля `features` в этой структуре не было. Значит выражение всегда `undefined`, все три условия ложны, и **панель семьи в rome, панель глобальных метрик в constantinople и история действий не отрисовывались никогда**.

Ничего при этом не падало: `tsc` был доволен, потому что типу `WorldState` в `types/index.ts` свойство `features?` объявлено — тип обещал то, чего бэкенд не шлёт.

## 2. Правка

`WorldState` получает `features`, и оно копируется из сценария там же, где уже копируется `global_metrics_display` — при загрузке сценария и повторно при загрузке сейва (сценарий, а не сейв, — авторитет для таких полей; сейвы, написанные до появления поля, приходят с `#[serde(default)]` и получают верные флаги при загрузке).

## 3. Лок и второй случай, найденный им сразу

Лок — `tests/scenario_conventions.rs::frontend_world_state_type_matches_the_rust_struct`: каждое свойство интерфейса `WorldState` из `src/types/index.ts` обязано существовать полем у Rust-структуры. Проверяется **одно направление**: поле Rust, которого фронтенд не знает, — не дефект; свойство TypeScript без поля за ним — ложь в типе.

**Первый же прогон упал** — и не на `features` (его я к тому моменту починил), а на **`actions_per_tick`**:

```tsx
// ControlPanel.tsx
const actionsLimitReached = worldState.actions_per_tick > 0
  && worldState.actions_this_tick >= worldState.actions_per_tick;
…
{worldState.actions_per_tick > 0 && ( <>Действия: {…} / {…}</> )}
```

`actions_per_tick` тоже жил только на `Scenario`. Значит `undefined > 0` — ложь, **счётчик «Действия: N / M» не появлялся никогда, и предел в интерфейсе не срабатывал**. Значения при этом настоящие: rome `2`, constantinople `3`, milan `3`. Движок предел соблюдает и отказывает в действии — то есть игрок узнавал о лимите не из счётчика, а из отказа.

Поле добавлено и копируется тем же путём.

## 4. Проверки

| | эталон `4aede1f` | после |
|---|---|---|
| лок | **падает** (`actions_per_tick`) | проходит |
| `features` в `WorldState` | нет | есть, копируется при загрузке сценария и сейва |
| `actions_per_tick` в `WorldState` | нет | то же |
| `cargo test` | 85 + 10 | **85 + 11** |
| `tsc --noEmit` | чисто | чисто |
| clippy `--workspace -- -D warnings` | чисто | чисто |
| `sim`, 5 прогонов | — | **побайтово** — правка только в пути приложения |

**Чего проверить нельзя:** что панели действительно отрисуются. Живого рендера Tauri на этой машине нет (то же ограничение, что у задачи `(E)` экрана победы). Доказано: поле доходит до структуры, которую возвращает команда, и заполняется из сценария на обоих путях загрузки.

**Про `features` лок сработал бы так же** — свойство объявлено в типе (`types/index.ts:98`), поля в Rust не было, значит оно попало бы в ту же разницу множеств. Наблюдением это не снято: удалить поле обратно и прогнать тест нельзя, компиляция падает раньше на конструкторах.

## 5. За скобками

- Гард §4 предыдущей задачи помечал `features` как известный дефект в списке исключений. Запись снята: дефекта больше нет.
- Остальные поля `Scenario`, не доходящие до фронтенда, лок не проверяет — он смотрит только на то, что фронтенд **уже обещал** в своём типе.
