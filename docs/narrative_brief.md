# Бриф нарратива

## Модель летописца (решение владельца, 2026-10-13)

- **Основная:** `claude-sonnet-5-5` через провайдер `claude_cli`. Игра запускает установленный Claude Code
  (`claude -p`) на подписке владельца — для личной игры (PR #269, #270).
  - Как включить: в настройках «Claude (подписка, claude CLI)», модель `claude-sonnet-5-5`.
  - Изоляция: пустой каталог, без инструментов, MCP, навыков, сессии и источников настроек; тайм-аут 300 с.
  - Отказ (не установлен, нет входа, лимит) показывается в окне, и хроника не попадает в книгу.
  - Для раздачи игры другим этот путь не годится: нужен API-ключ Anthropic (провайдер `anthropic`, та же модель).
- **Запасная:** DeepSeek v4-pro (`deepseek/deepseek-v4-pro-0813`) через nano-gpt. Подключать, когда исчерпан
  лимит подписки.

### Критерии

Сравнение — `investigation_model_compare.md`: шесть партий milan v2, по 60 хроник на модель, у каждой своя книга
и стоп-лист.
- **жёсткое условие** — хроник с чужой письменностью не больше 1 из 60;
- противоречия фактам движка;
- числа и ключи движка в тексте;
- зачины с даты и их повторы;
- рамка 4–6 абзацев;
- читаемый русский — по чтению образцов владельцем.

### Почему Sonnet

- **Условие прошли три модели:** Sonnet 5.5 (0), DeepSeek v4-pro (0) и DeepSeek v4.1-flash (1).
- **Sonnet:**
  - ни одной латиницы на 60 хроник;
  - инструкцию о зачине держит: 4 из 60 с даты;
  - 4–6 абзацев во всех 60;
  - факты на месте: лига против Милана, давление Флоренции на Сиену, регентство Лодовико;
  - старые ходы игрока как текущие не подаёт.
- **DeepSeek v4-pro** пишет богаче, но хуже как летописец:
  - 36 из 60 зачинов с даты или времени года;
  - длинные периоды;
  - на т. 25 (aggressive s9) приписал давление Милана на Геную Флоренции и подал «банковский союз Милана с
    Флоренцией» как действующий при лиге против Милана.
- **Шаг 3** (`investigation_chronicle_step3.md`):
  - противоречие на Sonnet одно — война с подчинённой Сиеной; причина во входе, исправлено;
  - стилистических формул в ≥ 3 хрониках партии — 1 против 9 у прежней модели.

### Повторять сравнение

**При выходе новых версий моделей сравнение надо повторить** тем же порядком:
1. Те же шесть партий (`chronicle_probe live` / `step`, `CHRONICLE_PROVIDER`, `CHRONICLE_MODEL`).
2. Таблица `model_compare/eval.py`.
3. Чтение образцов владельцем.
4. Разбор `model_compare/step3/`.

Точные ID — из каталога провайдера, с датой.
